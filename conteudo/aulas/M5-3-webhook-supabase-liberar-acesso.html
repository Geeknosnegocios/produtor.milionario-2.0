Eventos a Tratar

Todo webhook de pagamento tem eventos terminais. Tratar todos ou ter surpresas.

purchase.approved
Pagamento aprovado → INSERT na tabela enrollments, libera acesso
subscription.renewed
Renovação aprovada → UPDATE expires_at, mantém acesso ativo
purchase.refunded
Reembolso → UPDATE plan_status = 'cancelled', revoga acesso
subscription.cancelled
Cancelamento → UPDATE plan_status = 'cancelled'
purchase.chargeback
Chargeback → UPDATE + flag especial no perfil
purchase.abandoned
Carrinho abandonado → email de recuperação (opcional)

Estrutura da Edge Function

Código mínimo que processa o webhook e libera o acesso.

// supabase/functions/cakto-webhook/index.ts
Deno.serve(async (req) => {
  // 1. validar assinatura HMAC
  const sig = req.headers.get('x-cakto-signature');
  if (!verifyHmac(sig, secret, body)) return 401;

  // 2. parsear evento
  const { event, data } = await req.json();

  // 3. tratar por tipo
  if (event === 'purchase.approved') {
    await supabase.from('enrollments').upsert({
      user_id, course_id, plan_status: 'active'
    });
  }
});

Variáveis de Ambiente

Segredos que nunca entram no código. Configurados no painel Supabase.

CAKTO_WEBHOOK_SECRET = seu_hash_secreto_gerado
SUPABASE_URL = https://[ref].supabase.co
SUPABASE_SERVICE_ROLE_KEY = eyJ...chave_de_servico
COURSE_ID = uuid-do-seu-curso-na-tabela
# configurar no Supabase CLI
supabase secrets set CAKTO_WEBHOOK_SECRET=abc123...
supabase secrets set COURSE_ID=6de5fdcd-a0d3-...

# deploy da função
supabase functions deploy cakto-webhook --project-ref [ref]

Tabela Enrollments

Schema mínimo para controle de acesso.

-- migration SQL
CREATE TABLE enrollments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES profiles(id),
  course_id UUID NOT NULL,
  plan_status TEXT DEFAULT 'active',
  plan_type TEXT, -- 'one_time', 'monthly'
  expires_at TIMESTAMPTZ,
  external_id TEXT UNIQUE, -- ID da transação
  created_at TIMESTAMPTZ DEFAULT NOW()
);

Deduplicação: external_id UNIQUE previne liberar acesso duas vezes para o mesmo pagamento — bug crítico que pode custar dinheiro em reembolsos fraudulentos.

Segurança do Webhook

Sem validação de assinatura, qualquer pessoa pode liberar acesso fake.

⚠️
Sem assinatura
Qualquer pessoa POST na URL = acesso liberado. Nunca fazer isso.
🔐
HMAC-SHA256
Validar assinatura do header antes de processar qualquer evento
🔑
Service Role Key
Usar chave de serviço (bypass RLS) apenas dentro da Edge Function — nunca no frontend
📝
Log de eventos
Salvar cada evento recebido em tabela de log para auditoria futura

  • Service Role Key: NUNCA expor no frontend — só na Edge Function
